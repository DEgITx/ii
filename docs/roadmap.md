# ii — дорожная карта

Принцип: **вертикальные срезы**. Каждый этап заканчивается работающим, протестированным и измеренным результатом,
который можно показать через CLI `ii`. Архитектурные «швы» (Backend API, планировщик, state-значения, символьные
формы) закладываются с первого этапа, даже если реализация за ними пока простая, — чтобы позже не переписывать ядро.

Схема зависимостей:

```
0 Фундамент → 1 Ядро (IR + ii-ref) → 2 Быстрый ii-cpu → 3 LLM ─┐
                                                   └→ 4 ONNX/CV ─┼→ 5 Мульти-бэкэнд + GPU → 7 Расширение
                                    1 ──────────────────────────────→ 6 Обучение ──────────┘
```

Этапы 3 и 4 независимы друг от друга (порядок — по приоритету); 6 можно начинать после 2.

---

## Этап 0 — Фундамент

**Цель:** скелет проекта, в котором удобно и безопасно разрабатывать всё остальное.

- Репозиторий: git, `.clang-format`, `.clang-tidy`, `.editorconfig`, `.gitignore`, лицензия.
- CMake: структура таргетов по слоям (§2 архитектуры), `CMakePresets.json` (debug, release, relwithdebinfo, asan,
  ubsan, tsan; MinGW-GCC и Clang), опции `II_*`, экспорт пакета (`find_package(ii)`), механизм многократной
  компиляции ISA-специфичных файлов.
- `core`: `Status`/`Result`/`II_TRY`, логирование с пользовательским приёмником, интерфейс `Allocator` и
  выровненный аллокатор по умолчанию, `SmallVector`, `f16`/`bf16`, `MappedFile` (Windows + POSIX), `CpuInfo`
  (ISA, кэши, топология P/E-ядер), `ThreadPool` с `parallel_for`, таймеры.
- Тестовая и бенчмарк-инфраструктура: GoogleTest, Google Benchmark, `ctest`, первый roofline-замер.
- CLI: `ii info` (железо, ISA, кэши, ядра) и `ii --version`.
- CI: GitHub Actions — Linux (GCC/Clang), Windows (MSVC/MinGW), macOS.

**Готово, когда:** сборка зелёная на всех платформах CI; тесты `core` (включая исчерпывающие f16/bf16 и TSan для
пула потоков) проходят; `ii info` корректно описывает машину; бенчмарк `parallel_for` и roofline-замер работают.

---

## Этап 1 — Ядро: тензоры, IR, операции, ii-ref, исполнение

**Цель:** можно описать модель через builder API, скомпилировать и корректно исполнить на эталонном бэкэнде.

- `Tensor`, `Buffer`, `Device` (host), DType-таблица (включая описания блочных квант-типов).
- IR: `Graph`/`Node`/`Value`, символьные формы, атрибуты, `verify()`, текстовый формат (печать и разбор).
- OpSet v1: все примитивы + первые составные (softmax, layer_norm, rms_norm, gelu, silu, linear, sdpa) с
  разложениями; вывод форм; функции стоимости.
- Backend API (`Backend`, `Executable`, `KernelBackend`), `ii-ref` со всеми операциями.
- Runtime: `Context`, `Model` (из builder), `Program`, `Session`; простейший планировщик (один бэкэнд + фолбэк),
  планировщик памяти, ExecutionPlan, state-значения.
- Проходы: вывод форм, свёртка констант, DCE, разложение составных.
- Скрипты генерации эталонов (NumPy/PyTorch), харнесс `compare_backends`, генератор случайных графов.
- Публичный C++ API (первая версия) + C ABI (минимум) + пример `examples/mlp`.

**Готово, когда:** тесты соответствия всех операций против NumPy/PyTorch проходят; тесты проходов с численной
эквивалентностью; инвариант «ноль аллокаций в `run()`» проверен тестом; пример MLP исполняется через C++ и C API.

---

## Этап 2 — Быстрый ii-cpu

**Цель:** собственный CPU-бэкэнд, сопоставимый по скорости со зрелыми библиотеками, работающий на любом CPU.

- SIMD-слой, runtime-диспетчер ISA (`generic`, `avx2`, `avx_vnni`, `avx512`, `neon`, …), `II_CPU_ISA`.
- GEMM f32 (BLIS-подход, предупаковка весов), f16/bf16 веса; GEMV.
- Поэлементные операции и редукции с фьюзингом цепочек; softmax, нормализации, rope.
- Распараллеливание через `ThreadPool` с динамической раздачей (гибридные CPU).
- Планировщик: `ii-cpu` предпочтительнее, `ii-ref` — фолбэк для того, что ещё не ускорено.
- Проходы: фьюзинг шаблонов (linear+act, нормализации), упаковка весов.
- Профайлер + Chrome trace.

**Готово, когда:** все тесты операций проходят для `ii-cpu` на всех ISA (включая SDE для AVX-512); цели
микробенчмарков GEMM/поэлементных из [testing-and-benchmarks.md](testing-and-benchmarks.md) §4.2 достигнуты или
задокументирован разрыв и план; сравнение с OpenBLAS опубликовано в `bench/results/`.

---

## Этап 3 — LLM (первый «настоящий» сценарий)

**Цель:** `ii chat model.gguf` работает быстро на обычном CPU.

- Загрузчики: GGUF (mmap, zero-copy квант-тензоры), safetensors + HF `config.json`; фаззинг.
- Квант-типы и ядра: `q8_0`, `q4_0`, `q4_k`, `q5_k`, `q6_k` — эталон в `ii-ref`, быстрые GEMV/GEMM в `ii-cpu`
  (AVX2, AVX-VNNI, NEON dotprod).
- `sdpa` (flash-attention для CPU), KV-cache как state, символ `seq`.
- Архитектуры: llama (Llama 2/3, Mistral, TinyLlama), qwen2/2.5/3, gemma, phi.
- Токенизаторы (byte-level BPE, SentencePiece), шаблоны чата (подмножество Jinja), сэмплеры, стриминг.
- CLI: `ii generate`, `ii chat`, `ii bench --llm`; `ii quantize`.

**Готово, когда:** логиты tiny-llama совпадают с transformers; на реальной модели greedy-генерация совпадает с
эталоном на N токенов и перплексия в допуске; `tg128`/`pp512` в пределах 10% от llama.cpp на той же машине и
квантизации (или задокументирован разрыв и план).

---

## Этап 4 — ONNX и «классические» модели

**Цель:** запуск произвольных ONNX-моделей (CV, энкодеры, аудио).

- Собственный декодер protobuf, импорт ONNX (opset 13–21+), external data, таблица маппинга операций.
- Свёртки (im2col+GEMM → прямые/Winograd/depthwise), пулинги, batch_norm-фолдинг, раскладка NCHWc.
- `if`/`loop` (подграфы), распознавание attention-шаблонов в `sdpa`.
- CLI: `ii run` с `.npy/.npz`/изображениями, `ii inspect`.

**Готово, когда:** ResNet-50, MobileNetV2, BERT-base, YOLO-n дают результаты в допуске относительно ONNX Runtime;
задержка сопоставима с ORT CPU EP; ONNX-фаззер работает в CI.

---

## Этап 5 — Мульти-бэкэнд и первый GPU

**Цель:** библиотека сама выбирает между несколькими реальными бэкэндами и устройствами.

- Полноценный планировщик: стоимостная модель, разбиение графа, пересылки, события, ограничения памяти,
  автоматический offload слоёв, автотюнинг с кэшем, `ii inspect --plan` с объяснениями.
- Тестовый бэкэнд `ii-test-remote` для тестирования межустройственных сценариев без GPU.
- Плагинный ABI `ii_backend_plugin_v1`, загрузка плагинов.
- **Первый собственный GPU-бэкэнд** — `ii-vulkan` (универсальность) или `ii-cuda` (максимум на NVIDIA).
- **Первый сторонний плагин** — ONNX Runtime (закрывает длинный хвост операций ONNX).
- `ii check-backends`.

**Готово, когда:** дифференциальные тесты проходят на GPU-бэкэнде; модель, не помещающаяся в VRAM, автоматически
делится между GPU и CPU; планировщик выбирает лучший план на наборе моделей (сравнение с перебором вручную).

---

## Этап 6 — Обучение

**Цель:** обучение и дообучение моделей средствами ii на любом бэкэнде.

- Правила градиентов для всех операций, проход autodiff, фьюженные backward-операции.
- `nn::Module`, трассировка в граф, функции потерь, оптимизаторы (SGD, Adam, AdamW) как фьюженные операции.
- Шаг обучения как один `Program`, DataLoader, чекпоинты (safetensors).
- Mixed precision, gradient checkpointing, LoRA/QLoRA для LLM.
- CLI: `ii train`.

**Готово, когда:** проверка градиентов конечными разностями для всех операций; MNIST-MLP и маленький CNN достигают
эталонной точности; кривая обучения совпадает с PyTorch при одинаковой инициализации; LoRA-дообучение маленькой LLM
снижает loss на целевом наборе.

---

## Этап 7 — Расширение

По приоритетам, определяемым бенчмарками и запросами:

- второй GPU-бэкэнд (Vulkan/CUDA), `ii-metal`; плагины OpenVINO (включая Intel NPU), TensorRT, CoreML;
  oneDNN (AMX) / XNNPACK / KleidiAI — там, где бенчмарки показывают выигрыш;
- нативный формат `.ii` с предупакованными весами, `ii convert`;
- платформы: Android, iOS, WebAssembly (`wasm_simd128`), RISC-V (`rvv`);
- LLM: MoE, paged KV-cache и continuous batching, speculative decoding, грамматики, мультимодальность;
- серверный режим (`ii serve` с OpenAI-совместимым API);
- привязки: Python (nanobind), C#, Rust — поверх C ABI;
- минимальная сборка под конкретные модели (`II_MINIMAL`).
